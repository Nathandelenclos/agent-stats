User guide

Install agent-stats, check usage in your terminal, and open the dashboard on your machine.

Install

The published binaries include the local dashboard.

Homebrew on macOS

brew install nathandelenclos/tap/agent-stats

Linux packages

Download the .deb for Debian or Ubuntu, .rpm for Fedora, or .apk for Alpine. Each comes in amd64 and arm64.

Compare the package's SHA-256 hash with checksums.txt from the same release, then install it with your distribution's package manager. Download a release package.

Archives for macOS, Linux, and Windows

Choose the archive for your OS and processor (amd64 or arm64) on the Releases page. The macOS filenames use darwin. Compare the archive's SHA-256 hash with checksums.txt from that release. Extract the archive and put the executable on your PATH.

Install with Go

With Go 1.26.11 or later, this command installs the CLI and local JSON API. The dashboard URL shows a build notice.

go install github.com/Nathandelenclos/agent-stats@latest

Run your first report

After a session with a supported coding agent, run a report across all projects for the last seven days. The pager lets you read the report a page at a time.

agent-stats --all --since 7d | more

Start with the totals, then compare breakdowns by coding agent, model, or folder. Add --harness codex to focus on Codex, --json for machine-readable output, or --no-sync to reuse the index without re-reading logs.

From a project folder, agent-stats can select that project automatically. Pass --project DIR to select one explicitly, or --all to include every project regardless of where you run the command.

Open the dashboard

Start the local server across all projects with a release binary.

agent-stats serve --all

Visit http://127.0.0.1:7373 on the machine running the command. Indexing runs in the background. Select Re-index to pick up new log data, and press Ctrl+C in the terminal to stop the server.

Usage

Start with the totals, then filter by period and coding agent. See estimated cost over time and sort the tables by model, folder, or tool to find what drove a change. If the server detected a project, use the project control to switch scope.

Sessions

Sort the sessions or select a row to see the matching session's models, tools, subagents, and prompt signals. The active period and coding agent filters also apply to this list.

Prompts

Review prompts flagged for signals such as repetition, negation, or profanity. When the data is available, this view shows repeated requests, counts by folder, and flagged prompts with their source session and coding agent. Treat flags as a starting point for review. Pasted text can trigger them too.

Keep your data local

agent-stats opens session logs read-only. Its SQLite index contains full prompt text and lives in agent-stats/index.db under your user cache directory by default. Treat the index, exported reports, and screenshots as private. Titles and paths can reveal project or prompt details.

By default the web server listens on the local machine. Session details and prompt reviews show excerpts only on a loopback listener without --allow-remote. With --allow-remote, anyone who can reach the server can read reports and session metadata without a login. See the server security notes before changing this setting.

Troubleshooting

The report has no requests

Check that your coding agent has written a local session, clear any coding agent filter, and try a longer period with --all. If the dashboard is already open, select Re-index after a new session.

The browser shows a build notice or an older dashboard

Use a release binary for the packaged dashboard. To build from a checkout, regenerate web/dist and then build the Go binary again. This also replaces any stale frontend bundled in a previous local build. The frontend build needs Node.js 22.12 or later.

go generate ./web && go build -tags web .

Start the rebuilt executable from the checkout with ./agent-stats serve --all, or .\agent-stats.exe serve --all on Windows. See the build instructions for details.

The default port is busy

Choose another loopback port and open the address you pass to --addr.

agent-stats serve --all --addr 127.0.0.1:8080
