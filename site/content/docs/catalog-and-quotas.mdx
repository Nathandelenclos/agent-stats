## Catalog

```sh
agent-stats catalog --all --since 30d
agent-stats catalog --unused
```

Catalog lists installed items by coding agent alongside their recorded uses and last use, when the source exposes them. `?` means the logs cannot distinguish usage for that item. JSON represents that value as `null`. `--unused` selects installed items with zero recorded uses.

Open **Catalog** in the local dashboard, or press `c` in the terminal and `u` to toggle unused items. The report filters also apply to the catalog. [See the catalog coverage by coding agent](https://github.com/Nathandelenclos/agent-stats#catalog).

## Account quotas

Open **Quotas** in the local dashboard, or press `l` in the terminal and `r` to refresh. Available windows show the remaining percentage and reset time for the provider account.

- **Codex** uses the installed app-server and its current login when you open or refresh the view.
- **Claude Code** needs the standard status-line JSON on stdin. Forward it from your existing status-line script to `agent-stats quota record-claude` while keeping the script's current display. The snapshot is available for up to 15 minutes.
- **Antigravity CLI** reads the latest snapshot from its [status line](#antigravity-cli-setup).
- **GitHub Copilot** reads monthly account limits from the installed Copilot CLI via its existing sign-in. The RPC was verified on CLI 1.0.83.
- **Grok Build** uses the installed CLI's ACP billing extension to read the signed-in account's included usage window.
- **OpenCode Go** reads the 5-hour, weekly and monthly limits from a local OpenCode server with the experimental usage API, verified against v2.2.2 source. Set `AGENT_STATS_OPENCODE_URL` to the running server's numeric loopback origin, such as `http://127.0.0.1:4096`. The endpoint must be readable without additional HTTP credentials.

Account quotas are independent of project, period, and coding agent filters. The web Catalog and Quotas are available on a loopback server without `--allow-remote`.

### Antigravity CLI setup

Add this `statusLine` entry to `~/.gemini/antigravity-cli/settings.json`. Use the full path to `agent-stats`
if the CLI cannot find it on your PATH.

```json
{
  "statusLine": {
    "type": "command",
    "command": "agent-stats quota record-antigravity",
    "stack_with_default": true
  }
}
```

If you already use a custom status line, forward its JSON input to the same command from your existing script.
Run `/usage` in Antigravity CLI to refresh the provider data. Agent Stats shows enabled quota buckets with a
remaining percentage and a future reset time. A snapshot expires after 15 minutes and each bucket disappears
when its reset time passes. This integration uses the [CLI quota payload](https://antigravity.google/docs/cli/statusline/).

### Quota history

The local dashboard records quota observations when it checks providers. In **Quotas**, open the history to compare the past 30 days for a provider and window. Each observation includes when it was checked and the reset time when known.

Use `agent-stats query quotas --since 7d` to read recorded observations from the local index without polling providers. An old reading can differ from the current account quota. See the [CLI availability and filters](/docs/cli/#agent-analysis).
