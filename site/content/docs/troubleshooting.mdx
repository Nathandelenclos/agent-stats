## The report has no requests

Clear the coding agent filter, select all projects, and try a longer period.

```sh
agent-stats --all --since 30d --plain
```

Confirm your coding agent has written a [supported local log](/docs/coding-agents/). If you used `--no-sync`, remove it or choose **Re-index** in the dashboard.

## The dashboard shows a build notice

Install a [release binary](/docs/install/) for the packaged dashboard. If you are building from a checkout, regenerate the front and build the binary again. The front build needs Node.js 22.12 or later.

```sh
go generate ./web
go build -tags web .
./agent-stats serve --all
```

On Windows, start the rebuilt executable with `.\agent-stats.exe serve --all`.

## Copilot shows no model requests

Choose **GitHub Copilot CLI** for local CLI history or **Copilot Chat (VS Code)** for the supported IDE history.
Check **Sessions** for indexed conversations. Microsoft documents separate file diagnostics for VS Code Local and
Agent Host sessions. Capture is disabled by default and applies to sessions recorded after enabling it.
See [VS Code diagnostics](https://code.visualstudio.com/docs/agents/agent-troubleshooting/chat-debug-view).

GitHub provides [organization and enterprise usage reports](https://docs.github.com/en/copilot/reference/copilot-usage-metrics/usage-metrics-coverage)
with server-side counts for clients such as GitHub.com. Its [billing API](https://docs.github.com/en/rest/billing/usage)
reports credits billed to the personal, organization or enterprise account covered by that endpoint. These reports and
the local session index measure different things.

## The default port is busy

```sh
agent-stats serve --all --addr 127.0.0.1:8080
```

Then open [http://127.0.0.1:8080](http://127.0.0.1:8080).
